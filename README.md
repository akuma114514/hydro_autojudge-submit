# Hydro Sample Runner

从公开 Hydro 题面导入样例，用本地 C++17 编译器测试当前 `.cpp` 文件，并可通过 Edge 伴随扩展自动提交。

## 当前功能

- `Hydro: 导入题目样例`：粘贴普通题目链接，按题面公开样例导入，关联当前文件。
- C++ 编辑器右上角的烧杯按钮（`Hydro: 一键运行自测`）：编译当前文件，逐组运行样例，在“Hydro 样例自测”输出面板查看结果；也可从命令面板运行。
- Edge 伴随扩展的“将当前题目导入 VS Code”：把当前 Hydro 题面的样例直接关联到 VS Code 当前打开的 C++ 文件。
- 自动提交返回评测记录后，会等待评测完成并在提交提示中显示本次得分；若暂时无法读取分数，提示评测记录链接。
- 样例存于工作区 `.hydro-samples/`；再次导入会更新当前文件的记录。
- 只忽略输出的每行末尾空格与最后多余的换行。公开样例通过不等于网站评测 AC。

## 支持的样例写法

导入时识别**能从题面明确配对**的公开样例，两种写法均受支持：

1. **编号式**（Hydro 规范写法）：```` ```input1 ```` / ```` ```output1 ````，编号即测试点编号，多组按编号排序。
2. **标题式**：`## 样例`、`## 样例 1` 等标题下**成对**出现的两个代码块，第一个为输入、第二个为输出；
   也支持 `### 样例输入 1` / `### 样例输出 1` 这类显式标注。

两种写法都保留样例正文的换行，并把 CRLF 统一为 LF；只有换行的输入块按空输入处理。

下列情况会**明确报错而不猜测**：代码块数量不是成对的、只有输入没有输出、标题标注与代码块数量不符、
编号样例缺少输入或输出、输出块出现在输入之前、题面里根本没有可识别的样例。
插件只读取题面文本，**不抓取题目附件，也不读取评测数据（隐藏测试点）**。

调研依据与格式细节见 `docs/sample-format-research.md`。

## 结果展示

自测输出面板区分以下状态，并给出通过数：

- **编译失败 / 编译超时**：显示编译命令与完整编译器输出，并说明未运行任何样例。
- **通过**、**输出不符**、**运行错误（退出码）**、**超时**：逐组标注状态与退出码。
- **首处差异**：输出不符时标出首个不同行的行号、列号，并给出期望行、实际行与指示位置的 `^`。
  该比较与判定一致，忽略行末空格与末尾换行，因此报出的差异不会是被忽略的空白造成的假差异。
- **完整内容**：面板末尾按失败样例列出样例输入、期望输出与实际输出，便于逐字比对。

展示文案始终区分“本地样例通过”与“网站 AC”，不会把本地通过写成 AC。


## 安装与运行

在 VS Code 扩展视图右上角选择“从 VSIX 安装”，选中 `hydro-sample-runner-0.2.1.vsix`。自动提交和网页一键导入还需要单独安装 `edge-companion` 文件夹中的 Edge 伴随扩展，并完成配对。

1. 安装 VSIX 后，在 VS Code 中打开 `C:\Users\72467\Desktop\cpp`，并打开一个已保存的 `.cpp` 文件。若从源码开发，可在本项目按 `F5` 启动扩展开发宿主后再打开该文件夹。
2. 在设置中确认 `hydroSamples.compilerPath` 为 `C:\msys64\ucrt64\bin\g++.exe`（当前默认值）。若编译器安装在其他位置，改为实际路径。
3. 若导入 `frp-fan.com:36387` 的公开题目，在确认该站点后开启 `hydroSamples.allowUntrustedCertificate`。此例外仅用于所配置源站的题目抓取。
4. 从命令面板执行导入命令，粘贴题目 URL；再执行自测命令。

当前验证题目：`https://frp-fan.com:36387/d/shnu2026seed/p/B2002`，解析结果为一组空输入样例，期望输出 `Hello,World!`。

## 状态与限制

- 已在用户的 VS Code 与 Edge 会话中完成本地样例自测和一次真实自动提交；核心逻辑另有自动化测试。
- 样例解析支持上述两种明确配对的写法；仍不支持单块样例、交互题、客观题，以及需要题目附件或评测数据的场景。
- 自动提交默认关闭。启用方法详见单独提供的 Edge 伴随扩展说明。
- 重新导入会先询问是否覆盖当前文件的旧样例。网站证书链不受信任；不要将网站登录凭据交给抓取模块。

## 自动提交（开发验证阶段）

开启 `hydroSamples.autoSubmit` 后，只有全部已导入样例通过，才会将当前代码排队给本机 Edge 伴随扩展。先在 VS Code 执行“Hydro: 复制 Edge 配对信息”，按伴随扩展说明完成配对；在已登录的 Edge 中打开对应题目页。伴随扩展使用浏览器会话提交，VS Code 不读取密码或 Cookie。同一题目、同一份代码最多自动排队一次；评测结果请以网站记录为准。

运行核心测试：`node --test`。核心模块使用 Node 内置 API，无需安装 npm 依赖。

集成测试默认跳过，需显式提供编译器路径：

```powershell
$env:HYDRO_TEST_COMPILER = "C:\path\to\g++.exe"; node --test
```
# Hydro 侧边栏

点击 VS Code 活动栏的 Hydro 图标，可集中查看当前 C++ 文件关联的题号、题面、样例输入和预期输出，并点击“运行自测”查看实际输出、编译错误和运行错误。题面按原始文本显示；旧样例记录需重新导入才能显示完整题面。

开启 `hydroSamples.autoSubmit` 并配对 Edge 后，全部公开样例通过会排队提交，侧边栏显示最近一次提交状态、分数和评测记录入口。零分测试点显示站点返回的输入、预期输出、实际输出及错误信息；未开放的数据明确显示“站点未返回测试数据”。本地结果及最近提交按源文件保存，切换文件会切换内容。修改代码后需重新自测以更新结果。
