# Hydro Sample Runner

从公开 Hydro 题面导入样例，用本地 C++17 编译器测试当前 `.cpp` 文件，并可通过 Edge 伴随扩展自动提交。

## 首次使用：安装 → 配置编译器 → 运行一次样例

仅做本地样例自测，完成下面 4 步即可。网页一键导入和自动提交需要再完成后面的 Edge 配对。

### 1. 安装 VS Code 插件

- 准备 **VS Code 1.90 或更新版本**、支持 C++17 的 `g++` 编译器，以及发布包中的 `.vsix` 文件。插件不会自动安装编译器。
- 在 VS Code 按 `Ctrl+Shift+X` 打开扩展，点击右上角 `…` → **从 VSIX 安装…**，选择收到的 `hydro-sample-runner-*.vsix`。文件名以实际发布包为准。
- 如果安装后提示重新加载窗口，按提示操作。按 `Ctrl+Shift+P`，输入 `Hydro`，应能找到“Hydro: 导入题目样例”和“Hydro: 一键运行自测”。

### 2. 打开自己的代码文件夹

在 VS Code 选择 **文件 → 打开文件夹…**，打开你存放 C++ 代码的文件夹，再新建或打开一个 `.cpp` 文件并保存。不能只打开单个文件，也不能使用尚未保存的临时文件。

### 3. 设置编译器

按 `Ctrl+,` 打开设置，搜索 `hydroSamples.compilerPath`，填写你电脑上 `g++.exe` 的完整路径。默认值是 `C:\msys64\ucrt64\bin\g++.exe`，只有该文件实际存在时才可直接使用；其他安装位置请填写自己的路径。

在 VS Code 的 PowerShell 终端执行下面的命令，确认编译器可启动（路径需与设置一致）：

```powershell
& "C:\msys64\ucrt64\bin\g++.exe" --version
```

能看到版本信息后继续。如果尚未安装编译器，请先安装带 `g++` 的 C++ 工具链；已有编译器但不知道位置时，可执行 `where.exe g++` 查找。没有查到表示它不在 PATH 中，需要到安装目录寻找；在插件里填写完整路径后，无需额外配置 PATH。

### 4. 导入并完成第一次自测

1. 保持已保存的 `.cpp` 文件为当前编辑器，按 `Ctrl+Shift+P`，执行 **Hydro: 导入题目样例**，粘贴普通题目链接。
2. 默认站点为 `https://frp-fan.com:36387`。使用其他 Hydro 站点时，先在设置中修改 `hydroSamples.allowedOrigin`，填写 `https://域名:端口`，不包含题目路径。Edge 伴随扩展目前仅支持默认站点。
3. 如果导入时报证书错误，确认站点可信后，在设置中开启 `hydroSamples.allowUntrustedCertificate`，重新导入并在提示中选择“继续导入”。该选项仅用于配置站点的题目抓取，正常证书的站点无需开启。
4. 编写并保存代码，点击编辑器右上角烧杯按钮，或执行 **Hydro: 一键运行自测**。
5. 在 **Hydro 样例自测**输出面板查看编译结果与每组样例结果；也可点击左侧 Hydro 图标查看题面和样例。

**初始化完成的标志：**题目样例成功导入，并能看到编译结果和逐组样例结果。代码写错导致“输出不符”也说明自测流程已经运行；本地样例全部通过仍不代表网站 AC。

## 可选：Edge 网页导入与自动提交

需要发布包中的完整 [`edge-companion`](edge-companion/README.md) 文件夹，VS Code 与 Edge 应运行在同一台电脑上。

1. 在 Edge 地址栏打开 `edge://extensions`，开启 **开发人员模式**，点击 **加载解压缩的扩展**，选择包含 `manifest.json` 的 `edge-companion` 文件夹。不要选择 `.vsix` 文件或项目的上一级文件夹。
2. 保持 VS Code 打开，执行 **Hydro: 复制 Edge 配对信息**。
3. 点击 Edge 工具栏的扩展按钮，打开 **Hydro Sample Runner Bridge**，粘贴刚复制的完整内容，点击 **保存并检查**。配对信息包含本机访问令牌，请勿公开分享。
4. 在 Edge 打开默认站点的普通题目页，在 VS Code 打开已保存的 `.cpp` 文件。点击扩展中的 **将当前题目导入 VS Code**，确认 VS Code 出现题面和样例。已有样例时按提示确认覆盖。
5. 如果还需要自动提交，在 VS Code 设置中开启 `hydroSamples.autoSubmit`，在 Edge 登录 Hydro 并保持**同一道题目**的页面打开，再保存代码并运行自测。全部样例通过后代码会排队提交，伴随扩展最多约 30 秒后检查任务，VS Code 显示提交状态和评测记录。

只使用网页导入时，无需开启 `autoSubmit`。自动提交默认关闭，开启后每次全部样例通过都可能触发真实提交；同一题目、同一份代码最多自动排队一次。完整限制与操作说明见 [Edge 伴随扩展 README](edge-companion/README.md)。

## 初始化常见问题

| 现象 | 处理方法 |
| --- | --- |
| 命令面板中找不到 Hydro 命令 | 确认 VSIX 安装成功、VS Code 版本满足要求，再执行“Developer: Reload Window”重新加载窗口。 |
| 提示先打开工作区或保存 C++ 文件 | 使用“打开文件夹”，并在该文件夹内打开已保存的 `.cpp` 文件。 |
| 编译器无法启动、找不到文件 | 检查 `compilerPath` 是否指向实际的 `g++.exe`，用上面的 `--version` 命令验证；设置框中的路径不需要额外加引号。 |
| 题目链接不被允许 | 核对链接的协议、域名和端口是否与 `allowedOrigin` 一致，使用普通题目页链接。 |
| 导入时出现证书错误 | 确认站点可信后开启证书例外，并重新导入；Edge 访问也需单独确认能正常打开网页。 |
| Edge 提示未配对或配对格式不正确 | 从 VS Code 重新复制配对信息，完整粘贴，不要只复制端口或令牌。 |
| Edge 无法连接本地桥接 | 保持 VS Code 打开；若出现桥接启动失败或端口占用，关闭重复的 VS Code 窗口，或修改 `hydroSamples.bridgePort` 后重新加载窗口，再重新复制信息配对。 |
| 全部样例通过但未自动提交 | 确认已开启 `autoSubmit`、Edge 已配对且已登录，并打开同一道题的页面；等待约 30 秒。同一份代码已排队过时不会再次自动排队，查看侧边栏提交状态和网站记录。 |

## 当前功能

- `Hydro: 导入题目样例`：粘贴普通题目链接，按题面公开样例导入，关联当前文件。
- C++ 编辑器右上角的烧杯按钮（`Hydro: 一键运行自测`）：编译当前文件，逐组运行样例，在“Hydro 样例自测”输出面板查看结果；也可从命令面板运行。
- Edge 伴随扩展的“将当前题目导入 VS Code”：把当前 Hydro 题面的样例直接关联到 VS Code 当前打开的 C++ 文件。
- 自动提交返回评测记录后，会等待评测完成并在提交提示中显示本次得分；若暂时无法读取分数，提示评测记录链接。
- 样例存于工作区 `.hydro-samples/`；再次导入会更新当前文件的记录。
- 只忽略输出的每行末尾空格与最后多余的换行。公开样例通过不等于网站评测 AC。

## 支持的样例写法

导入时识别**能从题面明确配对**的公开样例，两种写法均受支持：

1. **编号式**（Hydro 规范写法）：```` ```input1 ```` / ```` ```output1 ````，编号即测试点编号，多组按编号排序。
2. **标题式**：`## 样例`、`## 样例 1` 等标题下**成对**出现的两个代码块，第一个为输入、第二个为输出；
   也支持 `### 样例输入 1` / `### 样例输出 1` 这类显式标注。

两种写法都保留样例正文的换行，并把 CRLF 统一为 LF；只有换行的输入块按空输入处理。

下列情况会**明确报错而不猜测**：代码块数量不是成对的、只有输入没有输出、标题标注与代码块数量不符、
编号样例缺少输入或输出、输出块出现在输入之前、题面里根本没有可识别的样例。
插件只读取题面文本，**不抓取题目附件，也不读取评测数据（隐藏测试点）**。

调研依据与格式细节见 `docs/sample-format-research.md`。

## 结果展示

自测输出面板区分以下状态，并给出通过数：

- **编译失败 / 编译超时**：显示编译命令与完整编译器输出，并说明未运行任何样例。
- **通过**、**输出不符**、**运行错误（退出码）**、**超时**：逐组标注状态与退出码。
- **首处差异**：输出不符时标出首个不同行的行号、列号，并给出期望行、实际行与指示位置的 `^`。
  该比较与判定一致，忽略行末空格与末尾换行，因此报出的差异不会是被忽略的空白造成的假差异。
- **完整内容**：面板末尾按失败样例列出样例输入、期望输出与实际输出，便于逐字比对。

展示文案始终区分“本地样例通过”与“网站 AC”，不会把本地通过写成 AC。


## 状态与限制

- 已在用户的 VS Code 与 Edge 会话中完成本地样例自测和一次真实自动提交；核心逻辑另有自动化测试。
- 样例解析支持上述两种明确配对的写法；仍不支持单块样例、交互题、客观题，以及需要题目附件或评测数据的场景。
- 自动提交默认关闭。启用方法详见单独提供的 Edge 伴随扩展说明。
- 重新导入会先询问是否覆盖当前文件的旧样例。网站证书链不受信任；不要将网站登录凭据交给抓取模块。

## 自动提交（开发验证阶段）

开启 `hydroSamples.autoSubmit` 后，只有全部已导入样例通过，才会将当前代码排队给本机 Edge 伴随扩展。先在 VS Code 执行“Hydro: 复制 Edge 配对信息”，按伴随扩展说明完成配对；在已登录的 Edge 中打开对应题目页。伴随扩展使用浏览器会话提交，VS Code 不读取密码或 Cookie。同一题目、同一份代码最多自动排队一次；评测结果请以网站记录为准。

运行核心测试：`node --test`。核心模块使用 Node 内置 API，无需安装 npm 依赖。

集成测试默认跳过，需显式提供编译器路径：

```powershell
$env:HYDRO_TEST_COMPILER = "C:\path\to\g++.exe"; node --test
```
## Hydro 侧边栏

点击 VS Code 活动栏的 Hydro 图标，可集中查看当前 C++ 文件关联的题号、题面、样例输入和预期输出，并点击“运行自测”查看实际输出、编译错误和运行错误。题面以 Markdown 预览显示，支持标题、列表、代码块、表格、链接和图片；旧样例记录需重新导入才能显示完整题面。

开启 `hydroSamples.autoSubmit` 并配对 Edge 后，全部公开样例通过会排队提交，侧边栏显示最近一次提交状态、分数和评测记录入口。零分测试点显示站点返回的输入、预期输出、实际输出及错误信息；未开放的数据明确显示“站点未返回测试数据”。本地结果及最近提交按源文件保存，切换文件会切换内容。修改代码后需重新自测以更新结果。
