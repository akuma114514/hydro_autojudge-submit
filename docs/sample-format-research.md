## 1. 官方文档口径

Hydro 官方文档《题目》一节明确说明题面为扩展 Markdown，样例的官方写法是带编号的围栏代码块，
编号即测试点编号，渲染时自动合并并左右分栏：

```input1
1 2
```

```output1
3
```

来源：
- [Hydro Docs · 题目](https://hydro.js.org/zh/docs/Hydro/user/problem)
- [Hydro 常见题型的制做心得](https://docs.hydro.ac/zh/docs/Hydro/user/problem-create)（其中 A+B 示例同样使用 ```` ```input1 ```` / ```` ```output1 ````）

即 `inputN` / `outputN` 是**规范写法**，也是本插件原有的行为，必须保持兼容。

## 3. 格式 B 的原文形态

以题 8《小王敲键盘》为例（原文摘录）：

```markdown
## 样例 1

```text
6
a2b3c1
```

```text
aabbbc
```

## 样例 2

```text
6
a3b2a-1
```

```text
aabb
```
```

可归纳的稳定特征：

1. 样例区由标题引入，标题形如 `## 样例`、`## 样例 1`、`## 样例2`、`### 样例 1`。
2. 每个样例标题下**紧跟两个**无编号围栏块：第一个是输入，第二个是输出。
3. 围栏信息串为 `text`，也可能是空串。
4. 多组样例重复该结构，标题序号递增。
5. 样例区之后的 `## 样例说明` / `## 数据范围` 等标题结束该区域——其中 `## 样例说明` 必须**不被**误当作新样例标题。

## 4. 关键边界与风险

- **CRLF**：B2005、B2029 的样例正文使用 `\r\n` 换行，B2025、P212 等使用 `\n`。解析必须统一，不能把 `\r` 留进样例。
- **空输入**：B2002 与 P1000 的输入块正文为空，必须保留为空串而非报错。
- **`样例说明` 陷阱**：题 7、9 存在 `## 样例说明`。若按“标题含『样例』”匹配，会把说明标题误判成样例组，导致配对错位。
- **表格与其它围栏**：题 6 的题面含数据范围表格；题 7 的行内代码含 `L`/`R`/`?`。解析只能消费样例区内的围栏，不能把题面其它代码块当成样例。
- **不该做的事**：不抓取 `additional_file`，不读取 `data/*.in|out`（评测数据）。题面元数据里确实暴露了隐藏测试点文件名与 etag，本插件继续明确忽略。

## 5. 结论：本插件支持的格式

| 格式 | 识别依据 | 状态 |
| --- | --- | --- |
| A：`inputN` / `outputN` | 围栏信息串显式编号 | 支持（原有，保持兼容） |
| B：样例标题 + 两个无编号围栏 | 标题 + 紧随的 2 个围栏，首个为输入 | 新增支持 |
| C：显式 `样例输入 N` / `样例输出 N` 标题 | 标题语言显式标注输入/输出 | 新增支持 |
| 其它 | —— | 明确报错，不猜测 |

不支持的典型情况：单个无编号围栏、只给出输入未给出输出、样例与文字混排无法确定配对、
交互题/客观题、以及评测数据与附件中的内容。
